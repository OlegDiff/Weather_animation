# Weather_animation

Интерактивная визуализация названий городов, в которой **погодные условия влияют на сами буквы**: дождь создаёт капли и волны, снег — снежный эффект, ветер — колебания и деформацию букв, солнце — свечение и движение облаков.

Проект создаётся как учебное, но расширяемое веб-приложение: от анимации с синтетическими данными до получения реальной погоды через API.

## Города и эффекты

Начальные города: **Dublin, Helsinki, Paris, Madrid**. Их расположение на макете сохраняется при переносе прототипа.

| Эффект | Код | Идея визуализации |
| --- | --- | --- |
| Дождь | `rain` | Капли, волны и деформации букв |
| Снег | `snow` | Снежная анимация |
| Ветер | `wind` | Колебания и изгибы букв |
| Солнце | `sun` | Жёлтое свечение и облака внутри контура букв |

Для условий, не соответствующих этим эффектам, предусматривается `neutral` — обычная надпись без активного погодного эффекта.

На первом этапе анимации работают с синтетическими сценариями; далее источником станет реальная погода.

## Технологии

- **Frontend:** HTML, CSS, JavaScript (без обязательного frontend-фреймворка).
- **Backend:** Python, FastAPI.
- **Погодные данные:** [Open-Meteo](https://open-meteo.com/en/docs) — планируемый поставщик.
- **Обмен:** HTTP и JSON.
- **Тестирование:** pytest для Python; проверки JavaScript будут определены при интеграции.
- **Контроль версий:** Git и GitHub.

На старте **не используем** Docker, PostgreSQL, Airflow, n8n и отдельную инфраструктуру frontend. Их можно добавить по мере появления реальных задач.

## Погодный API

`GET /api/weather` возвращает HTTP 200 с JSON даже при недоступности поставщика: проверяйте общий `status` и статус каждого города. Заголовок `Cache-Control: no-store` предотвращает кеширование ответа браузером; серверный кеш работает отдельно.

Контракт первой версии:

- `source`: Open-Meteo; `source_url`: ссылка для атрибуции; `data_kind`: weather_model; `mode`: live.
- `generated_at`: время формирования ответа в UTC, не время погодных данных.
- `refresh_interval_seconds`: 600; `retry_interval_seconds`: 60.
- `status`: ok, если все города fresh; иначе degraded.
- `cities`: Dublin, Helsinki, Paris и Madrid в фиксированном порядке. Каждый содержит `id`, `name`, `latitude`, `longitude`, `effect`, `status`, `error`, `data_time`, `fetched_at`, `missing_fields` и погодные показатели.
- `data_time`: время погодных данных в UTC; `fetched_at`: время успешного получения. При отсутствии данных оба null.
- `temperature_c`, `precipitation_mm`, `rain_mm`, `showers_mm`, `snowfall_cm`, `wind_speed_kmh`, `wind_direction_deg`, `cloud_cover_pct`, `weather_code` (WMO), `is_day` (0/1). Отсутствующие или некорректные значения — null, их имена перечислены в missing_fields.
- `precipitation_interval_seconds`: интервал накопления осадков из ответа поставщика; например 900 означает предыдущие 15 минут. Это не почасовая интенсивность.
- `status` города: fresh, stale или unavailable. При сбое `error` равен upstream_unavailable; иначе null.

Open-Meteo предоставляет текущие значения на основе погодных моделей, а не гарантированные измерения метеостанции. Единицы и интервал проверяются при нормализации. См. [документацию поставщика](https://open-meteo.com/en/docs).

### Выбор эффекта

Правила применяются по порядку. Численные пороги — настройки визуализации проекта, а не метеорологическая классификация:

1. snow: snowfall_cm > 0 или WMO-код 71, 73, 75, 77, 85, 86.
2. rain: rain_mm или showers_mm > 0, либо код 51, 53, 55, 56, 57, 61, 63, 65, 66, 67, 80, 81, 82, 95, 96, 99. Грозы и град пока используют дождевой эффект.
3. wind: скорость ветра >= 25 км/ч.
4. sun: дневное время, код 0/1, облачность <= 30%, все показатели осадков присутствуют и равны нулю.
5. neutral: остальные случаи, включая недостаток данных. Общие осадки без известного типа сами по себе не классифицируются как дождь.

### Кеш и сбои

Кеш хранится отдельно для каждого города в памяти одного процесса. Первый запрос загружает четыре города; следующие используют кеш 10 минут. Обновление происходит при запросе, фонового планировщика нет. На запрос поставщику установлен тайм-аут 5 секунд; первый ответ может ждать несколько последовательных запросов. Блокировка предотвращает дублирующие обновления при одновременных запросах.

При ошибке используются последние успешные значения с отметкой stale и прежними временными метками; при отсутствии кеша возвращаются neutral, unavailable и null вместо выдуманной погоды. Повторная попытка для проблемного города возможна через 60 секунд. Данные старше часа также помечаются stale. Старый кеш пока не удаляется по возрасту, поэтому интерфейс должен явно отображать этот статус. Перезапуск процесса очищает кеш.

В режиме «Реальная погода» frontend вызывает API и выбирает эффекты по стабильным идентификаторам городов. В режиме «Демо» сохраняются исходные сцены. neutral отображается обычной цветной надписью. Название Raris на странице сохранено; идентификатор погодного города — paris.

## Локальная разработка

Проверено на Windows с Python 3.14.2. Из корня проекта выполните в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --reload
```

Откройте http://127.0.0.1:8000/. Для остановки сервера нажмите Ctrl+C в терминале. Если окружение уже создано и зависимости установлены, достаточно последней команды. Активация окружения не требуется: используется его Python напрямую.

`backend/main.py` создаёт приложение FastAPI и отдаёт только содержимое `frontend/`. Путь к frontend вычисляется относительно main.py. Будущие маршруты API необходимо объявлять перед подключением статических файлов к `/`.

`requirements.txt` фиксирует версии установленных зависимостей, включая транзитивные. `.venv/` исключена из Git. Способ подключения статических файлов: [документация FastAPI](https://fastapi.tiangolo.com/tutorial/static-files/).

Сейчас сервер показывает исходную демонстрацию с синтетическими сценариями. Погодный API доступен по /api/weather, документация маршрута — /docs. Режим выбирается переключателем под картой.

## Демо и реальная погода

Откройте http://127.0.0.1:8000/ при работающем сервере. По умолчанию выбран режим «Демо»: три исходные сцены по 12 секунд, пауза и ручное переключение. Демо не обращается к погодному API.

Выберите «Реальная погода» под картой. Пока идёт первая загрузка, показываются обычные надписи. После ответа эффекты соответствуют погоде каждого города; позиция, цвет и название Raris сохраняются. Кнопка следующей сцены и индикатор демоцикла в этом режиме не используются. Пауза останавливает движение, но не обновление данных.

Под картой показаны эффект, температура, время погодных данных в часовом поясе браузера и состояние каждого города. Источник — Open-Meteo, указанный ссылкой. Неполные или устаревшие данные отмечаются явно.

Браузер запрашивает погоду при входе в режим и затем раз в 10 минут. При ошибке или неполной доступности повторяет запрос через минуту. Тайм-аут загрузки — 30 секунд. На сбой связи сохраняется последний эффект с предупреждением; при отсутствии данных используется neutral. Отсутствующий город, неизвестный эффект или некорректная временная метка также дают neutral. Изменения API применяются без сброса анимации, если эффект остался прежним.

Возврат в «Демо» отменяет текущий запрос и таймер обновления, запускает первую сцену. Запоздавший ответ не меняет выбранный режим. При прямом открытии index.html через file:// доступно только демо; для реальной погоды нужен FastAPI.

### Браузерные проверки

Тесты используют синтетические ответы через перехват сети и не зависят от текущей погоды. Установите requirements-dev.txt. На Windows используется установленный Microsoft Edge в фоновом режиме:

```powershell
$env:WEATHER_BROWSER_TESTS = "1"
.\.venv\Scripts\python.exe -m pytest -q
Remove-Item Env:WEATHER_BROWSER_TESTS
```

Для Chromium вместо Edge установите браузер командой `.\.venv\Scripts\python.exe -m playwright install chromium` и задайте `$env:WEATHER_BROWSER_CHANNEL = "chromium"`.

Проверяются демоцикл, пауза, ручная смена сцены, сопоставление городов по id, реальные эффекты, цвета neutral, отсутствие частых запросов, повтор после сбоя, устаревшие данные, возврат в демо и открытие файла напрямую. Без WEATHER_BROWSER_TESTS браузерные тесты пропускаются; тесты backend запускаются как обычно.
