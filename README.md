# Weather_animation

Интерактивная визуализация названий городов, в которой **погодные условия влияют на сами буквы**: дождь создаёт капли и волны, снег — снежный эффект, ветер — колебания и деформацию букв, солнце — свечение и движение облаков.

Проект создаётся как учебное, но расширяемое веб-приложение: от анимации с синтетическими данными до получения реальной погоды через API.

## Города и эффекты

Начальные города: **Dublin, Helsinki, Paris, Madrid**. Их расположение на макете сохраняется при переносе прототипа.

| Эффект | Код | Идея визуализации |
| --- | --- | --- |
| Дождь | `rain` | Капли, волны и деформации букв |
| Снег | `snow` | Снежная анимация |
| Ветер | `wind` | Колебания и изгибы букв |
| Солнце | `sun` | Жёлтое свечение и облака внутри контура букв |

Для условий, не соответствующих этим эффектам, предусматривается `neutral` — обычная надпись без активного погодного эффекта.

На первом этапе анимации работают с синтетическими сценариями; далее источником станет реальная погода.

## Технологии

- **Frontend:** HTML, CSS, JavaScript (без обязательного frontend-фреймворка).
- **Backend:** Python, FastAPI.
- **Погодные данные:** [Open-Meteo](https://open-meteo.com/en/docs) — планируемый поставщик.
- **Обмен:** HTTP и JSON.
- **Тестирование:** pytest для Python; проверки JavaScript будут определены при интеграции.
- **Контроль версий:** Git и GitHub.

На старте **не используем** Docker, PostgreSQL, Airflow, n8n и отдельную инфраструктуру frontend. Их можно добавить по мере появления реальных задач.

## Архитектура

```text
Open-Meteo API
     |
     v
backend/weather_api.py       Получение погодных данных
     |
     v
backend/weather_logic.py     Нормализация и выбор эффекта
     |
     v
backend/main.py              Собственный HTTP API (FastAPI)
     |
     | JSON
     v
frontend/app.js              Получение данных и управление состоянием
     |
     v
frontend/weather-effects.js  Отрисовка погодных эффектов
     |
     v
Браузер                      Названия городов и анимация
```

**Разделение ответственности:** Python получает и интерпретирует погодные данные; JavaScript отвечает за отображение и анимацию. Замена погодного API не должна требовать переписывания анимаций.

## Формат обмена данными

Backend планируется предоставить маршрут `GET /api/weather`, который отдаёт состояние всех настроенных городов. Пример структуры **синтетического** ответа:

```json
{
  "updated_at": "2026-10-12T10:00:00Z",
  "cities": [
    {
      "id": "dublin",
      "name": "Dublin",
      "effect": "rain",
      "temperature_c": 12,
      "precipitation_mm": 2.4,
      "wind_speed_kmh": 15,
      "wind_direction_deg": 230,
      "cloud_cover_pct": 95
    }
  ]
}
```

Это проектируемый **собственный формат API**, а не формат ответа Open-Meteo. Единицы измерения и период, за который измерены осадки, нужно явно согласовать при реализации.

## Получение и обновление погоды

1. Backend запрашивает погоду для заданных координат городов.
2. Приводит значения к единому формату и определяет основной эффект.
3. Сохраняет последний успешный результат в памяти процесса.
4. Frontend получает JSON от backend и плавно меняет анимацию.

Начальный ориентир — обновление внешних данных раз в **10–15 минут**. Анимация между обновлениями продолжает работать независимо. При временном сбое API отображается последнее успешное состояние с отметкой времени; при отсутствии данных используется `neutral`.

Правила выбора основного эффекта будут уточнены при интеграции. Черновой приоритет: **снег → дождь → сильный ветер → солнце при подходящих условиях → neutral**. Наличие облаков не означает солнечную погоду.

## Локальная разработка

Планируемая среда: **VS Code + Codex**, Git и Python.

После создания backend и файла зависимостей предполагаемый запуск будет выглядеть так:

```bash
python -m venv .venv
# Активируйте виртуальное окружение подходящей командой для вашей ОС
pip install -r requirements.txt
uvicorn backend.main:app --reload
```

Эти команды **пока не являются проверенной инструкцией запуска**: модуль `backend.main` и зависимости необходимо создать и протестировать. Точный URL приложения будет указан после настройки раздачи frontend через FastAPI.
